# Pace 开发计划 - Sprint 13: CS 架构启航 (身份验证与安全)

## 1. 目标
从纯本地应用转为支持后端验证的架构。建立用户基础表，实现手机号/微信登录，并处理“未登录态”的平滑降级。

---

## 2. 功能清单 (Task List)

### 2.1 用户模型设计 (User Schema)
* **字段：** `uid`, `phone`, `wechat_unionid`, `nickname`, `avatar`, `level` (FREE/PRO), `created_at`。
* **安全性：** 严禁存储明文密码，使用 JWT (JSON Web Token) 进行状态维护。

### 2.2 登录流程与人机校验
* **手机登录：** 接入短信验证码流程。
* **防机器人：** 在发送验证码前，必须通过图形验证码或人机校验组件。
* **微信登录：** 预留微信扫码/授权登录接口。

### 2.3 降级与路由逻辑 (Degradation Logic)
* **核心规约：** - 用户不登录时，APP 首页显著位置显示“离线模式”，数据读写仅限 IndexedDB。
    - 登录后，前端 Header 展示用户信息，并启动“云端同步预备”状态。
* **路由：** 不需要独立路由。使用全局状态（如 React Context 或 Redux）管理 `auth_status`，根据状态动态切换数据源。

### 2.4 用户管理基础 API
* 实现：注册、登录、退出登录、账号注销（彻底删除云端数据）。

---

## 3. 技术要求 (For Agent)
* **后端建议：** Node.js (NestJS 或 Hono) 或 Python (FastAPI)，配合 PostgreSQL。
* **中间件：** 实现一个 `authMiddleware` 校验 Token 有效性。
* **前端：** 保持现有的 Dexie 逻辑不变，作为底层的“离线缓存层”。

---

## 4. 给 Agent 的指令示例
> "现在我们要为 Pace 增加后端支持。
> 1. 请设计 PostgreSQL 的用户表结构。
> 2. 实现手机验证码登录接口，并在发送短信前加入简单的防刷逻辑。
> 3. 调整前端路由逻辑：如果用户未登录，保持现有的本地 IndexedDB 存储；如果登录成功，将用户信息存入 Context。
> 4. 请确保‘注销账号’功能能物理删除该用户在后端数据库的所有记录。"


# Pace 开发计划 - Sprint 14: 账号体系与显式数据接管

## 1. 产品核心原则 (First Principles)
* **权属隔离：** 登录态数据属于云端账户，离线态数据属于本地设备。登录是“云端接管”过程，登出是“物理清空”过程。
* **显式决策：** 严禁静默覆盖用户数据。在登录涉及本地数据冲突时，必须由用户显式选择“合并”或“清空（并提供导出）”。
* **平滑降级：** 登录失败或未登录时，系统必须自动退回到现有的离线模式，确保核心计时功能不受后端状态影响。

---

## 2. 功能清单 (Task List)

### 2.1 身份验证与安全体系 (Auth System)
* **多渠道登录：** 实现手机验证码登录及微信扫码/授权登录。
* **人机校验：** 在发送验证码前引入安全校验（如 Cloudflare Turnstile 或图形验证码），防止机器人刷量。
* **状态管理：** 建立全局 `authStatus` (Anonymous / LoggedIn)。UI 根据状态动态切换（如 Header 显示头像或登录按钮）。

### 2.2 登录时的“接管”决策逻辑 (Login Handover)
当认证成功后、拉取云端数据前，必须执行以下预检：
1. **本地扫描：** 检查本地 IndexedDB 是否存在任务/习惯/目标记录。
2. **场景 A (首次关联/新账号)：** 若云端无历史数据，弹出决策窗：
   * **选项 1：合并至云端。** 批量上传本地数据至后端，完成后进入同步模式。
   * **选项 2：清空并开始。** 提供“导出备份”按钮，用户确认后清空本地并登录。
3. **场景 B (非首次关联)：** 若该账号在云端已有数据，弹出警告：
   * **警告内容：** “登录将接管此设备，本地未登录时的操作数据将被清空。”
   * **操作：** 提供“手动导出”下载 JSON，或“确认清空并登录”。
4. **取消机制：** 用户可随时取消登录流程，完整保留本地数据并回到离线态。

### 2.3 物理登出与降级 (Logout & Degradation)
* **强力登出 (Force Logout)：** 1. 调用后端注销 API 清除 Session/Token。
  2. **物理抹除：** 执行 `db.delete()` 或 `db.clear()` 彻底清空本地所有 IndexedDB 表，不留任何痕迹。
  3. **重置：** 将应用状态切回离线模式，允许用户立即开始新的匿名操作。

### 2.4 超级管理员后台 (Admin Dashboard v1.0)
* **独立路由：** 仅限 `role === 'SUPER_ADMIN'` 访问 `/admin` 路径。
* **系统监控：** 查看总用户数、今日活跃数、系统负载及 API 耗时。
* **用户管理：** 支持搜索用户、封禁账号、手动调整用户等级（FREE/PRO）。

---

## 3. 技术规约 (For Agent)

### 3.1 接口设计
* `POST /api/auth/login`: 登录验证。
* `POST /api/sync/import-local`: 批量接收本地数据并存入云端。
* `GET /api/sync/pull-all`: 全量拉取云端数据。
* `POST /api/auth/logout`: 注销 Token。

### 3.2 数据处理要求
* **本地导出：** 在登录拦截弹窗中点击“导出”时，需直接调用现有的 JSON 导出逻辑，确保用户在数据被清空前拿到备份。
* **原子性：** 只有在“合并上传成功”或“用户点击确认清空”后，才能执行本地数据库的 `clear()` 操作。

---

## 4. 给 Agent 的指令示例 (Prompt)

> "请执行 Sprint 14：实现账号体系与数据接管逻辑。
> 1. 建立后端用户表及 JWT 验证机制，支持手机验证码登录。
> 2. **核心逻辑：** 登录成功后拦截页面跳转，若本地有数据，必须弹出对话框让用户选择‘合并到云端’或‘清空（提供 JSON 导出按钮）’。
> 3. 实现‘强制登出’：点击退出时，必须调用 db.clear() 物理删除本地 IndexedDB 的所有内容。
> 4. 实现一个极简的 /admin 页面，仅供超管查看用户总数。"


# Pace 开发计划 - Sprint 15: 云端多媒体存储 (OSS/S3/Vimeo)

## 1. 目标
将任务内容中的多媒体资源从本地存储/外部外链升级为受控的云端托管，支持图片和视频的直接上传，并根据用户等级实施配额管理。

## 2. 功能清单 (Task List)

### 2.1 云存储集成 (Object Storage)
* **后端网关：** 接入阿里云 OSS 或 AWS S3。
* **上传流程：** * 前端向后端申请“预签名上传链接 (Pre-signed URL)”。
    * 前端直接将文件推送到 OSS，减轻后端带宽压力。
* **视频支持：** 针对大体积视频，支持嵌入 Vimeo 或特定云视频托管链接。

### 2.2 Markdown 资源映射
* **自动替换：** 当用户在 Markdown 中粘贴图片或上传附件后，系统自动返回云端持久化 URL。
* **私有访问：** 确保图片链接具有一定的时效性或通过 CDN 鉴权，保护用户隐私。

### 2.3 等级与配额逻辑 (Quota System)
* **存储限制：** * 免费用户：限制总空间（如 500MB）或总文件数（如 10 张图/3 个视频）。
    * 高级用户：提供更大的空间和无限制的文件数。
* **超限提醒：** 当用户上传触发配额时，弹出友好的升级提示或清理建议。

## 3. 指令示例 (For Agent)
> "请实现 Sprint 15。1. 在后端接入阿里云 OSS，实现获取预签名上传地址的 API。2. 在前端 Markdown 编辑器中增加‘上传附件’按钮，上传后自动插入 OSS 图片链接。3. 在用户模型中增加 storage_usage 字段，每次上传后更新并校验是否超过等级限额。"


# Pace 开发计划 - Sprint 16: 服务端 OCR 算力中台

## 1. 目标
将 OCR 识别逻辑从前端迁移至后端。保护 API 密钥安全的同时，通过后端代理实现更复杂的识别策略（如手写体识别优化）和频率限制。

## 2. 功能清单 (Task List)

### 2.1 后端 OCR 代理服务
* **密钥安全：** 将腾讯云/百度云 OCR 的 SecretId/Key 存储在后端环境变量中。
* **统一接口：** 前端只需调用 `/api/ocr/recognize` 并上传图片，无需关心底层调用了哪个服务。

### 2.2 识别算法优化
* **智能切换：** 后端根据图片特征（或前端传参）自动选择使用“通用文字识别”还是“手写体识别”。
* **结构化清洗：** 后端在返回识别文本前，先利用正则或简单的 NLP 逻辑清洗杂质（如去除页码、特殊符号）。

### 2.3 频率限制 (Rate Limiting)
* **分级调用：** * 免费用户：每天限制 OCR 识别次数（如 1 次/日）。
    * 高级用户：享受高频次、高精度的识别服务。
* **缓存机制：** 同一张图片的 MD5 校验，若重复上传则直接返回缓存的识别结果，节省 API 成本。

## 3. 指令示例 (For Agent)
> "请将 OCR 逻辑搬迁到后端。1. 在后端创建 /ocr 路由，封装腾讯云手写体识别接口。2. 前端不再保存 API Key，改为上传 Blob 图片至后端获取 JSON 结果。3. 在后端增加 Redis 计数器，根据用户 UID 实现每日调用次数限制。4. 如果是免费用户且次数用完，请返回特定的错误码，前端据此弹出升级引导。"
