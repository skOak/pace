# Pace MVP 开发计划 (Local-First 架构版)

## 1. 核心技术栈 (Tech Stack)
* **框架:** Next.js (React) + Tailwind CSS + shadcn/ui
* **存储:** **Dexie.js** (IndexedDB 封装，本地优先)
* **部署:** 静态托管于 Ubuntu (Nginx)

---

## Sprint 1: 浏览器数据库与存储服务 (The Brain)
**目标：** 在浏览器中建立可靠的结构化存储，支持后续所有状态流转。

* **核心任务：**
  1. 使用 Dexie.js 初始化 `PaceDB`。
  2. **表结构定义：**
     * `tasks`: id, title, est_time, act_time, status (DRAFT/PENDING/RUNNING/PAUSED/COMPLETED/EXPIRED), tags, is_school_done。
     * `execution_logs`: id, taskId, startTime, endTime (记录计时的物理片段)。
     * `daily_anchors`: date (YYYY-MM-DD), start_anchor, end_anchor。
  3. 封装基础 CRUD 方法供 UI 调用。

* **给 Agent 的指令：**
  > "请使用 Dexie.js 创建一个名为 PaceDB 的数据库类。定义 Tasks, ExecutionLogs 和 DailyAnchors 三个表。请确保字段支持任务的状态流转和累计时长计算。提供基本的增删改查 API 接口。"

* **验收标准：** 在浏览器开发者工具的 IndexedDB 面板中能看到创建的表，且刷新页面数据不丢失。

---

## Sprint 2: 任务看板与基础交互 (The Body)
**目标：** 构建用户界面，实现任务的视觉管理。

* **核心任务：**
  1. **Today 视图：** 渲染任务卡片列表，区分“执行中”、“待办”和“已完成”。
  2. **创建任务：** 实现一个 Dialog 弹窗，支持录入任务名、预估时间（分钟）和标签。
  3. **Inbox 视图：** 简单列表展示状态为 `DRAFT` 的任务。
  4. 响应式适配：确保在手机端浏览器也能顺畅操作。
  5. 未执行过的任务可以进行删除。

* **给 Agent 的指令：**
  > "请基于 Next.js 和 shadcn/ui 创建首页布局。实现 Today 页面，能够从 Dexie 读取并展示今日任务。提供一个浮动按钮，点击后弹出 Dialog 录入新任务，并持久化到本地数据库。"

* **验收标准：** 能够手动录入 3 条作业，并在“今天”清单中准确显示。

---

## Sprint 3: 计时引擎与排他逻辑 (The Heart)
**目标：** 实现最核心的“单任务运行”与“锚点记录”。

* **核心任务：**
  1. **排他执行逻辑：** 点击“开始”任务 A 时，如果任务 B 正在 `RUNNING`，弹出二次确认弹窗。确认后，任务 B 设为 `PAUSED` 并记录 `endTime`，任务 A 设为 `RUNNING`。
  2. **时长累加：** 每次暂停或结束时，自动计算本次 `startTime` 到 `endTime` 的差值，累加到该任务的 `act_time`。
  3. **锚点记录：** 每天第一个任务进入 `RUNNING` 时，自动写入 `daily_anchors.start_anchor`。

* **给 Agent 的指令：**
  > "请实现任务的状态机转换逻辑。关键点：同一时间只能有一个任务处于 RUNNING 状态。开启新任务必须暂停旧任务并准确计算已用时长。同时，请在用户开启每日首个任务时，记录 start_anchor 时间点。"

* **验收标准：** 切换任务时会有弹窗确认；多次暂停/恢复后，任务的总实际用时计算正确。

---

## Sprint 4: 数据迁移与生命周期 (Security)
**目标：** 确保数据可备份，并处理任务的“过期”状态。

* **核心任务：**
  1. **备份功能：** 实现一键导出 `pace_backup.json`（包含库内所有表数据）。
  2. **恢复功能：** 支持上传 JSON 文件并全量覆盖本地 IndexedDB。
  3. **自动过期：** 每次应用启动时，检查非当日且未完成的任务，将其状态更新为 `EXPIRED`。
  4. **校内补录：** 实现“在校已完成”勾选逻辑，仅录入实际用时，不触发计时器。

* **给 Agent 的指令：**
  > "请为应用增加数据备份功能。编写一个 exportService 将所有 Dexie 表转为 JSON 文件下载。同时实现 importService。此外，请实现一个生命周期钩子，在每日首次加载时将昨天的未完成任务标记为 EXPIRED。"

* **验收标准：** 导出的 JSON 文件可以成功在另一个浏览器中恢复数据。

---

## Sprint 5: 效率洞察与收尾预测 (The Spirit)
**目标：** 将捕获的数据转化为对小朋友有用的“节奏感”反馈。

* **核心任务：**
  1. **偏差分析：** 在任务卡片上显示 `实际/预估` 的效率百分比。
  2. **收尾预测 (Pace Forecast)：** 实时计算：`当前时间 + 所有待办任务预估总时长 = 预计结束时间`。
  3. **简单复盘：** 在页面顶部显示今日已坚持的总时长和启动积极度（start_anchor）。

* **给 Agent 的指令：**
  > "请在 Today 页面顶部添加一个‘预计收尾时间’的显示。该时间需要根据当前剩余任务的预估量动态刷新。同时，请在 Insight 页面展示一个简单的列表，对比每项任务的预估和实际时长偏差。"

* **验收标准：** 首页能实时看到“还要多久能做完作业”的预测数值；完成任务后能直观看到自己预估得准不准。

## Sprint 6: 细节打磨与功能增强

### 1. 目标
修复 MVP 阶段遗留的数据显示 Bug，完善任务生命周期管理，并引入初步的激励机制与 OCR 录入入口。

---

### 2. 功能清单 (Task List)

#### 2.1 数据精准度与格式化 (Bug Fix & UI)
* **时长格式化：** 编写全局工具函数 `formatDuration`。
  * 将所有的分钟数显示改为 `x h y m` 格式（例如：`1h 20m`）。
  * 修复截图出现的异常数值 Bug（如 `302530m`），检查预估时长字段的边界值校验。
* **进度条修正：** 确保已完成列表中的进度条颜色和比例正确反映 `实际 / 预估` 的偏差。

#### 2.2 自动生命周期管理 (Lifecycle)
* **自动过期逻辑：** * 在应用启动时执行一次检测。
  * 逻辑：若任务的创建日期早于今天且状态不为 `COMPLETED`，则将其状态强制更新为 `EXPIRED`。到达每日 22:00 或设定时间，未完成的任务必须自动转为 Expired（已过期）状态，并记录在洞察中。这能反映出“负荷过重”或“放弃”的情况。
* **校内任务剔除：** * 优化“专注时长”统计逻辑。
  * 确保标记为“校内完成”的任务时长**不计入**当日的“系统专注总用时”，避免数据污染。「校内完成」的任务市场不计入当日专注总用时，但是要在洞察中有体现，这个数据不能丢，之后可以用于对比同一个任务，在校内完成和在校外完成，之间的效率对比；

#### 2.3 激励机制与转场仪式 (Incentives)
* **闪电启动奖励 (Spark Reward)：**
  * 判断逻辑：若当日 `start_anchor`（首个任务启动时间）在设定的黄金时段（如 17:00 - 18:00）内，Today 页面的首个任务卡片需添加一个特殊的**金色流光边框**或“闪电”图标。
* **专注转场仪式：**
  * 在点击确认框的“确认切换”后，进入新任务计时前，增加一个 **0.5s 的全屏淡入淡出遮罩**，中心显示：“深呼吸，准备进入 [任务名] 的时间。”

#### 2.4 洞察深度化 (Advanced Insights)
* **标签聚类分析：** * 在“洞察”页面增加一个统计模块。
  * 按 Tag（如 #数学, #英语）对偏差进行分组：显示“哪类任务我最容易低估时间”。tag除了用于聚类分析之外，在新建和编辑任务的时候，对于已有的标签，可以直接选择，而非每次都要输入，列出来供选择的标签按照历史使用频次进行排列；
* **收尾预测增强：** * 优化首页的“预计结束时间”算法。
  * 公式：`预计收尾 = 当前时间 + 所有待执行任务的预估时长 + 5分钟/任务(缓冲时间)`。

#### 2.5 数据管理与录入入口 (Entry)
* **备份文件名优化：** 导出 JSON 时，文件名需自动包含日期，格式为 `pace_backup_YYYY_MM_DD.json`。
* **OCR 录入 UI 入口：** * 在“收集箱”和“今天”页面右下角增加一个“拍照导入”按钮图标。
  * 本次 Sprint 仅需完成 UI 占位和图片上传预览逻辑，OCR 识别算法留待下个 Sprint。

#### 2.6 任务添加+号的逻辑优化
* **批量添加：** 现在手动添加任务，是单条添加，要额外多加一个「批量添加」，弹框出来是文本输入框，按照特定格式输入后，自动拆分成多条任务，如果时长未写，则默认填充预估时长。格式为下面两种：
  * 格式一：一行一个任务，每行任务类似：任务名称（必填）[#标签] [预估时长] [✓校内完成(放最后)]
  * 例如：
    * 数学 #数学,课内 60m ✓
    * 英语 #英语,课内 30m
    * 语文 #语文,课内 45m
  * 格式二：结构化的方式写入，下面例子中的title语文数学，最终是作为标签要在具体的任务中出现，如果和显式写下的标签重复，记得去重
  * 例如：
    * 语文
      * \- 预习第3课 ✓
      * \- 预习第4课 20m
    * 数学
      * \- 预习第3课 30m ✓
      * \- 预习第4课 #学而思，课外 30m

## Sprint 7: 宏观节奏与深度标签分析

### 1. 目标
从“关注单日”转向“观察长期趋势”，通过可视化手段建立孩子的长期节奏感，并利用标签系统提供量化的执行力反馈。

---

### 2. 功能清单 (Task List)

#### 2.1 Horizon 视图：周/月看板 (Visualizing Rhythm)
* **周看板 (Weekly Strip)：** * 在页面顶部或独立页面，展示最近 7 天的精简条形图。
  * **颜色映射：** 绿色（任务全完成且偏差小）、橙色（有任务超时或过期）、灰色（无任务）。
* **月度热力图 (Monthly Heatmap)：**
  * 模仿 GitHub 的贡献图，但颜色代表“ Pace 达成度”。
  * 帮助小朋友直观看到自己哪几周是“规律”的，哪几周是“混乱”的。
* **洞察页的周/月/年看板：** * 在“洞察”页面增加一个“日/周/月/年”切换下拉菜单。“日/周/月/年”切换后，洞察数据的展示方式也切换为对应的今日/周/月/年看板。
* **洞察页增加未完成而自动Expired的任务列表：** * 在“洞察”页面增加一个“未完成而自动Expired的任务列表”，展示未完成而自动Expired的任务，并给出相应的提示。根据选择的「日/周/月/年」筛选该时间周期类的自动过期任务。

#### 2.2 标签系统深度整合 (Tag Insight)
* **标签偏差聚类：**
  * 在洞察页统计各个 Tag 的平均效率指数（Efficiency Index = 实际 / 预估）。
  * **输出示例：** “#数学 类别通常比预估多花 15% 的时间，而 #阅读 类别通常比预估快 10%。”
* **标签时长分布：**
  * 展示一个简单的环形图，显示本周在不同科目/标签上投入的时间比例。

#### 2.3 能量锚点可视化 (Anchor Timeline)
* **起止点趋势：**
  * 绘制过去 7 天的“启动时点”和“结束时点”折线图。
  * **目的：** 观察小朋友的作业开始时间是否趋于稳定，结束时间是否在逐渐提前（效率提升）。

#### 2.4 智能偏差修正建议 (Smart Buffer)
* **逻辑：** 当某个标签的偏差连续 3 次超过 20% 时，在下次创建该标签任务时，系统弹出提示。
* **文案示例：** “根据你最近的 Pace，做数学作业通常需要比预估多 10 分钟，要不要把这次的预估时间调长一点？”

---

### 3. 技术逻辑说明

#### 3.1 数据聚合逻辑
* **聚合函数：** 编写 `getWeeklyStats` 和 `getMonthlyStats`，从 Dexie 读取指定日期范围内的所有 Tasks 和 DailyAnchors。
* **状态判定：** * `Success Day` = 当日无 Expired 任务且平均偏差在 [0.8, 1.2] 之间。
  * `Warning Day` = 当日有 Expired 任务或平均偏差 > 1.3。

#### 3.2 标签计算公式
* **Tag Efficiency：** `Average(Actual_Duration / Estimated_Duration) for each Tag`.

## Sprint 8: 视觉智能与快速录入 (腾讯云 OCR)

### 1. 目标
通过手机/iPad 摄像头直接拍摄作业本或备忘录，利用腾讯云 OCR 技术实现作业内容的自动化提取，极大降低手动录入的成本。

---

### 2. 功能清单 (Task List)

#### 2.1 移动端相机唤起 (Camera Access)
* **原生调用：** 适配 iOS/Android 浏览器。
  * 点击“拍照导入”按钮，触发 `<input type="file" capture="environment">` 弹出系统拍照菜单。
* **相册支持：** 同时支持从系统相册选择已有的作业截图。

#### 2.2 图像预处理 (Image Pre-processing)
* **压缩与转码：** 在前端使用 Canvas 对拍摄的高分辨率照片进行压缩（建议控制在 1MB 以内），并转换为 Base64 格式以适配腾讯云 API 要求。
* **预览功能：** 在发送请求前，展示拍摄的照片预览，并允许用户简单裁剪（Crop）核心作业区域。

#### 2.3 腾讯云 OCR 集成 (Service Integration)
* **API 接入：** 对接腾讯云“通用印刷体识别”或“手写体识别”接口。
* **结构化解析：** * 将识别出的长文本按照换行符或序号（如 1., 2.）自动拆分为独立的任务条目。
    * **自动标签：** 匹配关键字（如“数”、“英”、“练”）自动预设标签。

#### 2.4 批量审核与入库 (Review & Confirm)
* **核对清单 UI：** 弹窗展示识别出的任务项，允许用户在入库前修改标题、手动分配预估时长。
* **批量添加：** 这个功能逻辑实际上是，拍照识别（通常是批量任务）-> 进入批量添加任务编辑页面 -> 用户确认后，将所有任务批量写入 IndexedDB，状态设为 `PENDING`（待执行）。批量任务添加是前面的Sprint已经实现的功能。

#### 2.5 apikey的本地管理
* **配置页入口：** 在“设置”页面增加一个“OCR API Key”输入框。用户输入后，加密\*号显示。
* **数据存储：** 将 API Key 加密后存储在 IndexedDB 中。
* **使用逻辑：** 在调用腾讯云 OCR API 时，优先使用用户配置的 Key；如果用户未配置，则报错提示用户输入。
