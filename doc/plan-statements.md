# Pace 开发计划 - Sprint 12: 指南针 (项目宣言与手册)

## 1. 产品核心原则 (The Soul of Pace)
* **诚实面对偏差：** 文档不应强调“提效”，而应强调“对齐”。让用户明白，Pace 的目标是缩短“我以为”与“实际上”之间的距离。
* **反焦虑设计：** 强调“零追债”原则，每一天都是新的开始，文档应传递这种“心理韧性”。
* **工具的隐形化：** 文档应引导用户把精力花在“做”上，而非“管理”上。

---

## 2. 功能清单 (Task List)

### 2.1 独立 TAB「指南」 (Handbook Tab)
* **交互形式：** 增加一个名为「指南」或「手册」的侧边栏/标签页。
* **阅读体验：** 采用单栏长文布局，左侧提供文章目录（Anchor Links），右侧为 Markdown 渲染的内容区域。支持图片与视频嵌入（复用 Sprint 9 的逻辑）。

### 2.3 内容架构规划 (Content Map)
Agent 需预设以下三个核心模块的占位符内容：

#### A. 我们为什么出发 (Why Pace?)
* **背景：** 解释“规划谬误”——我们总是习惯性低估任务难度。
* **目的：** 培养“时间体感”。通过每天的预估与反馈，让抽象的时间变成可以被触摸、被感知的物理量。

#### B. 三大核心支柱 (The Trinity)
详细说明三个模块的不同用法：
* **任务 (Tasks)：** 处理突发的、单次的行动。重点在于“当下”。
* **习惯 (Habits)：** 维持生活的节拍。重点在于“规律”。
* **目标 (Goals)：** 应对长线挑战。重点在于“拆解”与“耐心”。

#### C. 实战场景指南 (Scenarios)
提供具体场景的 Pace 实践建议：
* **场景一：放学后的作业高峰期。** (如何利用习惯自动生成清单，如何使用闪电启动)
* **场景二：周末的跨日大作业。** (如何将 Goal 拆解为 Session 领入今日)
* **场景三：当计划赶不上变化时。** (如何使用全属性编辑动态修正，如何接受 Expired 任务而不产生压力)

---

## 3. UI 布局与文案风格要求

### 3.1 视觉风格


* **排版：** 极简主义。大字号标题，充足的行间距。
* **插图：** 允许在文档中通过 Markdown 插入展示 Pace 核心逻辑的示意图（如计时圆环的颜色含义说明）。

### 3.2 文案口吻 (Copywriting Tone)
* **去 AI 化：** 严禁使用“旨在”、“赋能”、“全方位解决方案”、“卓越体验”等词汇。
* **建议表达：** 使用“为了让你看清时间”、“我们试着把大象塞进冰箱”、“如果今天没赶上这班车，没关系”等更具人情味的表达。

---

## 4. 技术实现建议 (For Agent)
* **数据驱动内容：** 指南的内容建议存储在一个独立的 `guide_content.json` 或直接写在组件常量中，方便 Simon 随时手动微调文案。
* **复用组件：** 必须复用 Sprint 9 开发的 Markdown 渲染器和视频播放组件，保持视觉统一。
