# Pace 开发计划 - Sprint 18: 时间完整性与追溯修正

## 1. 产品核心原则
* **容错性：** 承认遗忘是人的本能，系统应提供“后悔药”，但必须基于物理时间逻辑。
* **真实性：** 所有的手动修正必须通过“时间冲突校验”，确保一个人在同一时刻只能做一件事。
* **可视化反馈：** 通过线性时间轴让用户直观看到“时间的流逝”与“记录的空洞”。

---

## 2. 功能清单 (Task List)

### 2.1 线性时间轴组件 (Timeline View)
* **可视化呈现：** 在「今天」和「洞察」页面引入横向/纵向时间轴，展示当日已记录任务的物理分布。
* **冲突高亮：** 若数据逻辑出现重叠，时间轴对应区域显示红色。

### 2.2 任务时间追溯编辑器 (Retroactive Editor)
* **精准编辑：** 任务详情页增加“修正时间”入口，支持通过时间选择器（Time Picker）修改 `start_at` 和 `end_at`。
* **冲突校验引擎：** * 在保存修改前，检索当日所有其他任务。
    * 逻辑：新时间区间不得与已有任务的 [start, end] 区间产生交集。
    * 若有冲突，提示：“该时间段你正在执行 [任务A]，请先调整该任务。”

### 2.3 异常时长自动纠偏 (Auto-Correction)
* **幽灵计时器检测：** 若任务运行超过 4 小时且未手动停止，系统主动挂起并标记为“待确认”。
* **引导补录：** 在时间轴的空白处增加“+”号，点击可快速创建“补录任务”，自动填充该空白时段。

### 2.4 数据标记与统计隔离
* **标记位：** 数据库 `tasks` 表增加 `is_adjusted` 和 `adjustment_reason` 字段。
* **统计倾向：** 在分析“预估准确度”时，手动调整过的数据应给予较低的置信度评分，并在 UI 上用小图标标注。

---

## 3. UI 布局建议



* **交互逻辑：** 拖拽时间轴上的边缘可以快速拉长或缩短任务时长，类似于日历应用（Google Calendar）的操作体感。
* **补录对话框：** 简单直接。询问：“你刚才在做什么？” + “大概从几点到几点？”

---

## 4. 给 Agent 的指令示例

> "请实现 Sprint 18 的时间修正逻辑。
> 1. 在任务编辑弹窗中，允许用户修改任务的‘开始时间’和‘结束时间’。
> 2. 编写冲突检测算法：修改后的时间区间不能与当天其他已完成的任务重叠。
> 3. 实现一个简单的线性时间轴，展示今天各个任务的分布情况。
> 4. 如果任务运行时长异常（例如超过 5 小时），在下次打开 App 时提示用户修正结束时间。"
