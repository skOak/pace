# Pace 生产环境上线前 CheckList：身份验证体系准备

在应用从本地测试环境真正推向公网进行生产环境 (Production) 部署之前，手机短信验证和人机校验模块必须从 `Mock`（打桩）状态切换为真实生效状态，以免发生安全漏洞。

## 1. 真实“手机短信验证码”准备工作
当前开发环境中，内存里存着生成的随机码，且默认放行了 `888888`。上线前需要：

- [ ] **移除测试后门**
  在 `src/app/api/auth/login/route.ts` 中，找到验证判断条件：
  ```typescript
  // 上线前必须删除 && code !== '888888'
  if (!isValid && code !== '888888') { 
      return NextResponse.json({ error: '验证码错误或过期' }, { status: 401 })
  }
  ```

- [ ] **接入真实短信服务提供商 (SMS Provider)**
  在 `src/app/api/auth/send-code/route.ts` 中，用如阿里云短信服务 (Aliyun)、腾讯云系统 (Tencent) 或 Twilio 等 SDK 发送真实的短信息验证码。

- [ ] **防内存污染与多实例升级 (Redis)**
  目前 `src/lib/verificationStore.ts` 仅仅依靠 Node.js 的运行时全局变量 `Map` 存储：
  - 如果部署为无状态环境（如 Vercel/Serverless）或分布式架构多节点时，短信请求和登录请求往往落不到同一台主机。
  - **建议**：在此步骤采用 `Redis` 替代本地 Map，不仅可防溢出，还能天然利用 Redis 的 `EXPIRE` 属性做五分钟验证码过期丢弃处理。

## 2. 真实“Cloudflare Turnstile”防御准备
目前前端采用的是 Cloudflare 提供的测试 `SiteKey: 1x000...AA`，它始终默认通过并未作反爬校验。上线前需要：

- [ ] **注册真实凭据并加入域名白名单**
  前往 Cloudflare Turnstile 官方控制台，注册新站点，并将最终的线上公网域名（如 `pace.app`）配置到域名白名单中。

- [ ] **部署系统环境变量 (.env)**
  替换测试密钥，为平台引入真实的 Key：
  - **前端公钥**：`NEXT_PUBLIC_TURNSTILE_SITE_KEY=您的真实_SiteKey`
  - **后端私钥**：`TURNSTILE_SECRET_KEY=您的真实_SecretKey`

- [ ] **补全服务端核对链路 (Server-side Verify)**
  前端拿到 Token 后不能视为安全，必须在后端发短信前（`send-code/route.ts`），拿此 Token 秘密地向 Cloudflare 发送核对请求：
  ```typescript
  // 伪代码示例：向 Cloudflare 验证
  const verifyRes = await fetch('https://challenges.cloudflare.com/turnstile/v0/siteverify', {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: `secret=${process.env.TURNSTILE_SECRET_KEY}&response=${turnstileToken}`
  })
  const outcome = await verifyRes.json()
  if (!outcome.success) throw new Error("人机校验不通过！可能存在的脚本挂机刷量")
  ```

---
*注：当前系统成功登录后的 Token 生命周期限制恒定为 **30 天**。过期后将利用底层隔离和 Middleware/Me 接口能力，丝滑强制降级回本地无痕模式，确保在脱离网络时业务正常开展。*
